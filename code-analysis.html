New test

Mobile menu shows 'Sign In' link that navigates to /login

frontend/tests/navigation.spec.ts

The mobile menu login link was also renamed but is not covered by any existing test, leaving a gap in mobile navigation regression. Verifying it renders with the correct label and routes to /login protects against future regressions on the mobile path.

Coverage check: Checked all tests in navigation.spec.ts, auth.spec.ts, home.spec.ts, products.spec.ts, cart.spec.ts, and about.spec.ts. None interact with the mobile hamburger menu or assert the mobile login link. This is not a duplicate.

View proposed test code ↕ 
import { test, expect } from '@playwright/test';

test.describe('Navigation — mobile menu', () => {
  test('mobile menu shows Sign In link that navigates to login page', async ({ page }) => {
    // Use a narrow viewport to trigger the mobile menu
    await page.setViewportSize({ width: 375, height: 812 });
    await page.goto('/');

    // Open the mobile menu via the hamburger button
    const hamburger = page.locator('button[aria-label*="menu" i], button[aria-label*="open" i], header button').filter({ hasNot: page.locator('a') }).first();
    await hamburger.click();

    // The mobile Sign In link should be visible and point to /login
    const mobileSignIn = page.getByRole('link', { name: /^Sign In$/i });
    await expect(mobileSignIn).toBeVisible({ timeout: 5_000 });
    await expect(mobileSignIn).toHaveAttribute('href', '/login');

    // Clicking it should navigate to the login page
    await mobileSignIn.click();
    await expect(page).toHaveURL('/login');
  });
});
